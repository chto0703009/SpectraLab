# Engineering and Scientific Responsibility

The GNU General Public License defines the legal terms under which SpectraLab is distributed.

This document addresses a different subject: the engineering and scientific responsibilities associated with using measurement software.

It complements the license. It does not replace or reinterpret it.

---

## Engineering Responsibility

SpectraLab assists engineering decisions.

It does not make engineering decisions.

Engineers remain responsible for:

- interpreting measurements,
- selecting appropriate methods,
- evaluating uncertainty,
- judging whether results are reasonable,
- drawing engineering conclusions.

Engineering judgement always remains with the engineer.

---

## Scientific Responsibility

SpectraLab assists scientific work.

It does not determine whether scientific conclusions are valid.

Measurements should be:

- repeatable whenever practical,
- documented,
- traceable to the measurement procedure,
- independently verified when important.

Software output is part of scientific evidence. It is not scientific proof.

Extraordinary measurement results should be independently verified before they are used to support scientific conclusions.

Scientific conclusions remain the responsibility of the scientist.

---

## Software Quality

SpectraLab is developed using engineering practices intended to reduce defects.

These include:

- regression testing,
- quality gates,
- documentation review,
- real instrument verification,
- release checklists.

These practices reduce risk.

They do not eliminate risk.

No software can be guaranteed to be free from defects.

Passing all tests demonstrates that no known regressions have been detected by the current test suite. It does not prove that the software is free from errors.

---

## Measurement Responsibility

A measurement result is influenced by the complete measurement chain, including:

- instrument condition,
- calibration,
- reference standards,
- measurement geometry,
- environmental conditions,
- operator procedure,
- software configuration,
- data handling.

Reliable software contributes to reliable measurements.

It cannot guarantee them.

Unexpected measurements should always be investigated before conclusions are drawn.

---

## Intended Use

SpectraLab is intended for education, research, engineering and laboratory measurement workflows.

Users are responsible for determining whether SpectraLab is appropriate for a particular application.

Before using SpectraLab results in research, engineering, industrial processes, safety-related applications or published work, users should verify the measurement setup, calibration, exported data and conclusions.

---

## Open Source

SpectraLab is open-source software.

Community contributions can improve the project, but contributions must be reviewed, tested and documented before becoming part of an official release.

Open development does not remove the need for engineering verification.

---

## Final Statement

Reliable software supports reliable measurements.

Reliable measurements support sound science and engineering.

Scientific conclusions remain the responsibility of the scientist.

Engineering decisions remain the responsibility of the engineer.

Measure once.
Save forever.
Verify always.
